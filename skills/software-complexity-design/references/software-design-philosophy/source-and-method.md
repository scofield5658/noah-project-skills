# 来源、许可与研读方法

## 概念来源

本资料受以下著作启发：

- John Ousterhout, *A Philosophy of Software Design*
- 作者官方页面：<https://web.stanford.edu/~ouster/cgi-bin/aposd.php>

未发现允许把书籍正文、译文、完整原则列表、章节复述或作者公开摘录复制进 MIT 仓库的明确再分发许可证。公开可访问不等于允许再发布。

因此，本目录：

- 不复制完整英文原则句、译文、图表或章节案例叙述；
- 不记录私人持有文件的名称、哈希或本地路径；
- 使用独立编写的主题化总结、评审问题和通用案例；
- 保留少量英文技术术语，用于准确归因和跨语言识别；
- 不纳入第三方受保护表达；来源链接只用于归因，不表示复制或再许可链接内容。

## 研读方法

- 区分作者主张、通用工程推论和本仓库的应用建议。
- 对经验性主张保留适用边界，不把启发式原则机械升级为规则。
- 用独立控制面验证设计：变化传播与遗漏风险、知识归属、契约负担、恢复确定性和演进摩擦。
- 把具体案例抽象成可检查的问题，再回到当前代码、配置和业务事实。
- 当来源、翻译或许可存在疑问时，优先缩短引用、独立总结或移除。

## 术语使用规则

英文术语只承担来源识别作用，不直接作为结论。首次出现时先说明当前系统中可观察的结构问题，再在括号中标注术语。

例如，与其只写 `information leakage`，应说明“同一状态含义由多个模块分别解释，修改时必须同步更新”。与其只写 `deep module`，应说明“调用者通过较小的接口成本获得完整能力，而不需要理解内部步骤”。

术语及对应评审问题集中维护在 [principles-and-red-flags.md](principles-and-red-flags.md)。如果术语与当前证据不匹配，停止套用术语并按实际依赖重新判断。
