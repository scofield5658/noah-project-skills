# 复杂度决策画布与验证实验

本文件提供一套独立的决策画布，用于把复杂度思想转成架构、TDD 契约和大型项目演进的验证动作。思想来源与采用边界见 [software-design-philosophy/source-and-method.md](software-design-philosophy/source-and-method.md)。

## 1. 先写可被推翻的决定

每次评审先写一句候选结论：

> 在 `[前提]` 下，由 `[责任方]` 提供 `[稳定能力]`，把 `[内部复杂性]` 留在边界内；如果 `[反证条件]` 出现，则重新评估。

这句话必须包含：

- 当前要做出的一个决定；
- 依赖的事实和假设；
- 谁承担结果与恢复责任；
- 什么证据会推翻决定。

如果一句话无法写清，先缩小决定，不要直接画完整系统图。

## 2. 建立五份证据包

五控制面不是固定步骤。按当前风险先收集最可能推翻方案的证据。

### 恢复证据包

- 迟到、缺失、重复和修正数据如何进入；
- 补采、重新加工、回退、补偿和重跑的顺序；
- 已消费结果和外部副作用如何处置；
- 重新收尾和最终对账的门槛。

### 演进证据包

- 最近几次真实变化修改了哪些位置；
- 哪些兼容约束要求双路径；
- 最小可迁移切面和撤回条件；
- 下一次真实变化如何验证收益。

### 契约证据包

- 调用者真正表达的业务意图；
- 输入、结果、冲突、错误和版本含义；
- 外部行为测试是否依赖内部步骤；
- 权限和默认值是否改变业务结果。

### 变化证据包

- 当前需求与一个相邻变化的修改位置；
- 消费者、触发入口、配置、监控和操作流程；
- 必须临时掌握的上下文；
- 修改前无法直接发现的影响点。

### 知识证据包

- 数据格式、业务口径、状态、不变量和恢复语义的解释者；
- 同一含义被重复实现的位置；
- 状态写入点、契约、配置与运行证据；
- 责任冲突或无人负责的决定。

## 3. 先过硬门槛，再谈优劣

候选方案必须先满足以下门槛：

| 门槛 | 不满足时的处理 |
|---|---|
| 业务正确性与权限不被削弱 | 淘汰候选 |
| 存量兼容或迁移路径明确 | 补迁移方案，否则淘汰 |
| 恢复责任和关键失败信号明确 | 补齐责任，否则淘汰 |
| 数据版本、幂等和最终对账可证明 | 增加验证设计，否则淘汰 |
| 变更范围与撤回条件可控 | 缩小切面，否则淘汰 |

通过硬门槛不代表最优，只说明候选值得比较。

## 4. 用九问选择候选

九问按“先保可恢复，再看能否演进，最后比较日常使用成本”的顺序组织。
问题数量、分组和顺序由本仓库五控制面独立推导，不复现来源中的方案比较清单。

### 恢复控制

1. 发生错误或数据修正时，哪个候选更容易恢复到可证明的一致状态？
2. 哪个候选能让补采、重新加工、回退、补偿和重跑各有明确入口且不重复副作用？

### 演进控制

3. 哪个候选可以从一个可观测、可撤回的小切面开始，而不是一次性替换？
4. 下一次真实变化到来时，哪个候选能用修改位置、上下文和遗漏点验证收益？

### 契约控制

5. 哪个候选让常见调用直接表达意图，并保留必要错误和权限边界？
6. 哪个候选的外部行为测试最少依赖内部顺序、内部状态和大规模 mock？

### 变化与知识控制

7. 哪个候选减少跨代码、配置、监控和操作流程的同步修改？
8. 哪个候选让关键口径、状态和恢复语义拥有更明确的权威解释者？

### 综合取舍

9. 候选消除的长期成本，是否足以抵消新增接口、部署、迁移、观测和团队协作成本？

九问不计总分。任一答案依赖未经确认事实时，标为待确认并给出验证方式。

## 5. 用实验而不是口号验证

### 架构切分实验

场景：核心服务与候选预处理服务之间需要重新划分边界。

实验：

1. 选择一种真实输入和一个相邻变化；
2. 分别模拟“核心内聚”和“独立预处理”；
3. 记录两者的规则解释位置、结果版本、恢复入口和消费者影响；
4. 只有独立服务形成稳定结果且减少多方重复理解时才保留该候选。

### TDD 契约实验

场景：场景测试需要组合多个低层接口并 mock 多个模块内部状态。

实验：

1. 写出调用者可观察的结果、不变量、错误和恢复；
2. 设计两个不同粒度的契约；
3. 用同一组行为示例测试两个契约；
4. 比较前置条件、mock、编排步骤和错误表达；
5. 先选择责任与契约，再进入实现级红绿重构。

### 大型项目演进实验

场景：每个新业务场景都要求修改状态、调度、监控和操作脚本。

实验：

1. 从最近变化中选一个重复修改切面；
2. 建立旧路径兼容、影子观测和撤回开关；
3. 只迁移一个场景；
4. 用下一次真实变化测量修改位置、所需上下文和遗漏点；
5. 指标未改善时停止扩展，不把迁移完成当成成功。

## 6. 决定记录

最终只保存未来修改者需要的内容：

| 字段 | 内容 |
|---|---|
| 决定与适用前提 |  |
| 被排除候选及证据 |  |
| 五份证据包的关键结论 |  |
| 硬门槛验证 |  |
| 九问中的主要取舍 |  |
| 兼容、观测和撤回路径 |  |
| 重新评估条件 |  |

决定记录不是方案全文。它用于让下一次变化能快速复查当前边界是否仍然成立。
