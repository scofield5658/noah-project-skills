# 子任务类型选择

## 适用范围与元数据

仅支持 Product、Task、Improvement 三类主任务及关联 Bug；不创建主任务，不为 Bug 拆子任务。空间、父类型、实际层级节点、允许的子类型和关系方向均从当前公共 `gitee-team-manager` 能力取得。

技能包不携带任何真实空间的配置快照。以下 key 是可能遇到的识别示例，不代表目标空间一定存在、允许或有权创建：前端 `FE_Subtask`、后端 `BE_Subtask`、数据开发 `shujukaifa`、普通文档 `wendangzhuanxie`、技术方案 `jsfa`、其他 `OT_Subtask`。自定义 key 以目标空间实际元数据为准；工作维度与平台类型分别记录。

## 选择与执行规则

1. 读取主任务、空间详情和类型元数据，核对 `itemTypeScheme.hierarchy` 中该主任务实际所在父节点。不能把同类型不同节点的子类型取并集，也不能用全局类型列表或历史快照代替核验。
2. 用户指定类型时优先核对；未指定时，按工作含义匹配当前节点实际允许的专用类型。普通文档与技术方案分别匹配，前端工作不自动追加自测或 SQL。
3. 专用类型缺失时，只使用用户已经针对当前空间、父类型和工作维度明确确认的替代规则，并验证替代类型当前可用。没有该授权时列出允许候选并询问，不自动把所有工作归为“其他”。替代不改变实际维度、标题、范围、人员或父任务，Manifest 记录选择原因和授权范围。
4. 父节点无任何可用子类型时保留草案，不借用其他节点配置，不自动新建平台类型或改变父任务。原生子类型缺失不妨碍单独核验关联 Bug 的能力；Bug 仍需实际关系配置和授权。
5. 元数据查询失败或层级不明确时记为“类型校验未完成”，不认定类型不存在；创建前动态解析 objectId，记录名称、key 和选择依据。
6. 配置允许不等于账号有创建权限。查重覆盖所有分页、原生子任务和关联缺陷；历史类型不同但工作相同也须检查。查询不完整不得证明无重复。

## 合成示例

DEMO 空间的某个 Task 节点允许 `FE_Subtask` 和 `OT_Subtask`。用户要求数据开发，技能先展示缺少专用类型的事实；用户确认对该节点使用 `OT_Subtask` 后，Manifest 保持 `dimension=data` 并记录替代原因。若下一次父节点或空间不同，重新核验，不能继承本例的授权。
