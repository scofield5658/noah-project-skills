# Jira 与 Wiki 能力矩阵

先逐项探测，再执行对应操作。工具缺失、认证失败、权限不足或调用失败均视为该能力不可用；只报告缺口，不走替代的未授权路径。

| 操作 | 最小能力 | 不可用时行为 |
| --- | --- | --- |
| 查询父任务和子任务 | Jira 读取 | 不查询；仅用用户提供的信息生成本地草案。 |
| 查询主任务完整子任务管理清单 | 原生子任务查询 + 缺陷关联查询 | 保留已取得的事项并标注不完整，不能只查原生层级就报告完整。 |
| 查询 Wiki 远程链接 | Jira 远程链接读取 | 不发现额外关联；只处理用户在描述中明确给出的链接。 |
| 读取明确 Wiki 页面 | Wiki 只读 | 不读取、不搜索、不抓取；标记“关联 Wiki 未读取”。 |
| 校验人员与任务类型 | Jira 元数据读取 | 草案标注“未校验”；创建前要求用户提供准确值或启用校验能力。 |
| 核对 Team 父子类型配置 | 父事项详情、空间层级及事项类型元数据读取 | 保留草案，标记类型校验未完成；不能依据历史映射认定当前可创建。 |
| 创建子任务 | Jira 创建 + 已确认 Manifest | 不创建；保留预览。 |
| 更新主任务受控字段 | Jira 描述更新 + 已确认补丁 | 不更新描述；不整体替换描述。 |
| 创建后回查 | Jira 读取 | 仅报告创建接口的返回值，并说明无法独立回查。 |

## 平台能力

Team 操作复用已安装 `gitee-team-manager`，其运行时、认证和参数遵循当前 SKILL.md；Wiki 只读能力独立探测。每项操作单独核验能力，不因详情可读就假定创建、编辑、关联均有权限。

| 操作 | 最小能力 | 缺失时行为 |
| --- | --- | --- |
| 默认报告人及人员校验 | 当前用户、用户查询 | 保留草案，不猜账号或继承负责人 |
| 缺陷创建/维护 | Bug 类型及字段读取、创建或编辑 | 保留草案，不写入 |
| 缺陷关联预检 | 关系类型及方向读取、现有缺陷关联完整查询 | 不创建依赖该关联的新缺陷 |
| 建立缺陷关联 | 具体事项关联写入 | 标记能力缺口，不以其他关系替代 |

## 写入前最低门槛

创建要求：用户确认精确 Manifest、可用创建能力、父任务 key 有效、重复检查已完成，且每条任务的标题/类型已明确、父子类型已校验、报告人已解析、负责人由用户指定并校验。

描述更新要求：用户确认字段值和补丁、可用描述更新能力、受控字段位置可唯一识别。

Wiki 永远只读；本 Skill 不调用任何 Wiki 创建、更新、删除或附件写入操作。

缺陷额外要求：测试负责人明确、至少一个合法目标、缺陷关联定义及现有关系核验完整。详见 [人员与缺陷规则](people-and-bugs.md)。
