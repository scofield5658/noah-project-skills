# 前端实施指南

用于页面、组件、状态逻辑、字段转换及相关前端问题修复。以已授权目标推进，简单改动不先制造一份大型方案。

## 确定允许修改的范围

读取相关入口、相邻实现、调用方、样式与测试约定，以及项目提供的运行命令。保护已有未提交内容；不覆盖不属于本次任务的修改。

将用户目标映射到具体改动及完成条件。若已有方案，核对方案与当前代码的差异。范围、接口语义或兼容性发生冲突时先说明并收敛；可独立完成的范围内工作继续推进。

## 完成一个可验证的行为

1. 优先复用行为一致的组件、hook、工具、请求层和样式能力；确有不同语义时保持明确的独立边界。
2. 状态放在拥有该行为的最小合理范围，避免把派生值存成额外状态；跨组件共享须有实际消费方。
3. 对齐 props、事件或 callback 的参数、触发时机、返回值和默认行为。共享接口变更要检查已有调用方，不能只验证新页面。
4. 在合适边界完成字段转换，明确展示与提交差异；避免重复转换、隐式类型转换和丢失空值语义。
5. 对异步链路处理过期结果、重复提交、错误恢复和资源释放。选择项目已有的取消、请求序号或状态管理机制，不强制引入新库。
6. 沿用设计系统，检查布局变化、键盘操作、焦点、可读标签及相关错误提示。不要为普通业务改动重新定义品牌或全局样式。

例如，虚构的“资料目录”页面在切换分类时更新子分类选项：须确保旧分类请求晚返回不会覆盖新分类；子分类值的清空与回填遵循已知需求，不能自行把空值改成任意默认值。

## 修复与验证

修复缺陷时先建立复现路径、失败用例或可靠的静态因果证据。环境限制无法复现时说明证据和假设，避免把推测性修补宣称为已修复。

| 变化 | 优先验证 |
| --- | --- |
| 文案或局部样式 | 实际显示、相关布局和交互；项目已有的适用检查 |
| 工具、校验或字段转换 | 正常输入、实际存在的空值和关键边界，使用现有测试框架 |
| 表单、异步交互、状态 | 主路径、切换或重入、失败重试、旧响应及清理行为 |
| 共享组件、接口或类型 | 已有消费方、默认值兼容、代表性回归及类型检查 |

从贴近改动的检查开始，按影响扩大。测试、构建和浏览器操作使用项目已有能力；不要仅为本技能新增框架。验证失败先判断是否由本次改动引入，报告未关闭的问题，不顺手修复无关故障。

完成时说明改了什么、为何这样改、执行了哪些验证及结果、哪些条件尚未验证。构建通过不证明真实接口可用；模拟测试不等于真实联调。没有运行权限或环境时给出具体补验路径，不虚报完成。
