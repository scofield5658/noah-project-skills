# 交接与固定输入

交接材料只保留接手所需的事实，不转发整个会话。交互通道里只放摘要和可解析引用；完整内容放在新的运行仍能读取的位置。

交接正文只写接手所需的事实。认证材料、秘密和附带访问参数的地址都不放进去。

## 触发条件

出现下列任一情况时写出交接记录，而不是只在聊天里说“做完了”：

- 一个阶段产生了候选成果。
- 执行者受阻，需要协调者或下一位执行者从某个位置继续。
- 已确认的决定要成为后续输入。
- 外部操作已经发生，或者结果仍然未知。
- 本轮结束前需要留下恢复点。

只在同一次连续执行里自己接着做、而且没有别人需要读取时，不单独发布交接记录。一旦执行可能结束、换人、换实例或进入并行，就必须发布。

## 发送者步骤

1. 确认成果已经存在于持久位置，并能按准备交出的版本读回。上传或写入失败时，不要发布交接。
2. 填写 [templates.md](templates.md) 的交接记录。至少包含：
   - 目标、范围、当前阶段和完成条件。
   - 固定输入，以及实际读过的关键来源和版本。
   - 已完成工作、准确成果版本和验证结果。
   - 未完成事项、失败尝试，以及哪些判断需要重核。
   - 已确认决定、原始出处和适用范围。
   - 已经产生或结果未知的外部操作。
   - 下一责任人、第一个未完成动作、所需条件和成功判断。
3. 成果还没有经过采用或复核时，状态写成“候选，待复核”。
4. 先发布正文，再把发布回执中的标识补进任务关联或回执，不要求正文预先写上自己还没有生成的版本号。不要为了把自身标识写回正文而反复重新发布。
5. 在返回入口留下摘要和可解析引用。摘要不能替代正文。

发送者的交接物是持久交接记录和返回入口上的引用。

发送者完成标准：另一位没有主会话的接收者，只凭引用就能打开约定版本；记录里没有凭据。

## 接收者步骤

1. 按引用打开正文，核对实际版本。需要时核对哈希、代码提交或构建标识。
2. 版本不一致、打不开或与任务说明点名的输入不符时，停止依赖这份材料的步骤，向协调者报告准确缺口。不要改读别的版本。
3. 候选成果可以读取和核验。读取时不要先把状态改成已采用。采用仍由协调者在核验后写入。
4. 返回简短回执：输入可用还是受阻、实际读到的版本、发现的缺口、下一步。
5. 回执不是业务批准，也不是质量通过。下载成功只说明文件到达；标识一致只说明版本相同。

接收者的交接物是回执。

接收者完成标准：回执里的版本与发送者发布的版本一致，或明确写着受阻原因。下一步是一个动作，不是“稍后处理”。

## 固定输入

- 派单和交接中的每份依据都带可识别版本。
- 执行中发现必须引用新材料时，先报告协调者，把新版本写进任务说明后再使用。
- 有效反馈改变了输入时，协调者形成新基线，并标出受影响的既有结论。不要在在途任务上看不见地换成另一份输入。
- 会话摘要可以用来定位记录，不能代替成果、外部操作结果或批准原文。

## 完成标准

- 接手所需的七类事实都在持久正文里，或者某一类明确写了“无”。
- 通道消息能解析到正文版本。
- 候选和已采用没有混用。
- 发送者能读回成果，接收者的回执确认了同一版本或报告了打不开。
- 材料没有纳入认证材料、秘密或附带访问参数的地址。
