# 恢复与对账

恢复顺序固定为五步：**找到正确任务，读取固定材料，核对当前实际状态，对账既往操作，补做第一个未完成动作。** 没有走完前一步，不重发可能产生副作用的操作。

状态说明发生了什么。证据说明为什么可以这样判断。子任务被标成完成，不能单独证明结果正确。

## 触发条件

出现下列任一情况时，先做恢复检查点，再决定继续、等待或重做：

- 上下文被压缩，或手头只有会话摘要。
- 执行实例已经退出，要在新实例里继续。
- 外部调用超时、没有回执，或本地解析失败。
- 成果已经发布，但任务关联还没更新。
- 必需输入打不开。
- 收到重复事件、旧事件，或任务已被取消、替代。
- 准备重试任何可能已经成功的外部操作。

## 步骤

1. 用整体目标、任务关联和协调者记录定位任务。从子任务事件启动时，也要先找回整体任务和未完成依赖，再处理这个事件。
2. 读取权威任务记录、点名版本和已经发布的成果。摘要只用来找这些材料。
3. 对照目标系统的当前状态，区分已执行、未执行和未知。
4. 把既往操作分成请求对象、输入版本、执行结果、解析结果、真实回执和未知项。
5. 只补第一个还未完成、且不会重复副作用的动作。结果仍未知时，暂停相关副作用，交给协调者。

耗时阶段在可交接的工作边界上保存成果，不等退出钩子。中断前没有持久化的内容，标成无法恢复或需要重做。重做前仍要先排除重复副作用。

## 情形对照

| 情形 | 处理 | 不要做 |
|---|---|---|
| 上下文压缩或摘要不完整 | 读取权威任务记录、关键来源和持久成果 | 只复述旧摘要，或把摘要当完成证明 |
| 执行实例退出 | 新实例从已发布材料恢复 | 假定旧磁盘、旧进程或未发布草稿还在 |
| 外部操作超时 | 查询目标和原始回执，确认已执行、未执行或未知 | 为了得到正常响应立刻重发 |
| 本地解析失败 | 把操作本身和结果解析分开，检查完整返回和目标状态 | 把解析错误当成外部写入失败 |
| 成果已发布，任务关联未更新 | 保留已发布版本，只补关联并读回 | 重做整个任务或重新上传全部成果 |
| 必需输入不可读 | 停止依赖步骤，报告准确缺口，继续不依赖它的部分 | 改用最新稿、旧缓存或其他任务的材料 |
| 已取消或被替代 | 核对停止范围，保留已完成成果，处理相关等待 | 因为旧事件到达而重新开工 |

同一结果被重复通知时，先看处理记录。已经采用或已经派发的后续任务不重复做。成员失败时，协调者要能从返回入口看到失败；返回入口本身依赖自动触发而宿主没有这种触发时，在退出记录里写明这个缺口和人工通知人。

## 重试与未知结果

- 对支持幂等请求的服务，恢复同一次操作时保持原请求和原键。
- 对不支持幂等的服务，用可查询对象和操作记录对账，不为了重试临时发明新的副作用。
- 对账后仍未知，就暂停相关写入并交给协调者。不要写成“恰好执行了一次”。
- 普通交接只保留脱敏后的必要事实，不复制可能含有凭据的大段原始日志。

操作记录至少能分开：请求对象、输入版本、执行结果、解析结果、真实回执、未知项。

只读失败也要有停止条件。按任务已定的重试策略执行；没有新信息、修复或条件变化时，不由执行者另起无限重试循环。记录尝试及观察，交协调者明确何时恢复，独立的本地分析仍可继续。重新尝试时说明这次要验证什么，不能把“再试一次”当作原因已经排除。

工具恢复、输入可读和业务结果正确是不同结论。恢复后补查实际受影响的行为；需要改需求、实现、测试材料还是证据，先按 [evidence-and-change.md](evidence-and-change.md) 核对，不能因一次失败自动修改代码或全部重跑。

## 交接物

恢复检查点，包含：

- 任务关联和当前协调者。
- 读到的固定材料及版本。
- 目标的实际状态，以及已执行、未执行、未知的划分。
- 第一个未完成动作；若还不能做，写明缺少的条件。
- 明确不再重放的操作和原因。

## 完成标准

- 五步顺序没有跳步。
- 未知操作没有被重放。
- 已发布版本没有因为关联缺失而被重新上传。
- 无法恢复的未持久化工作被标成需要重做，而不是被写成已完成。
- 检查点本身放在新运行能够读取的位置。本地环境会随运行销毁时，不能只写在那次运行的本地磁盘上。
