# 前端审查参考

当本次变更主要是前端代码时读取本文件。

## 重点

1. 函数和方法行为是否正确。
2. 组件用法是否符合项目习惯。
3. props 和 callback 契约是否清楚。
4. 是否引入了多余层级。

## 函数和方法行为

- 检查工具函数、事件处理、映射逻辑和派生状态，重点找会直接影响行为的问题。
- 普通 UI 改动不要上来就要求完整测试套件，先看承载行为的函数是否可靠。
- 如果新增了可复用且逻辑较重的 helper，要判断实现是否容易理解，是否值得补一个轻量测试。

## 组件用法

- 看组件是否按项目里相似组件的方式使用。
- 留意不合群的组合方式、临时 wrapper、孤立样式方案。
- 如果共享组件或 hook 已经覆盖同类行为，重复实现要指出。

## Props 和 callback 契约

- props 名称要能表达业务含义，并和项目命名习惯接近。
- 可选/必填 props 要和已有组件契约一致。
- callback 的参数、调用时机、返回值要和下游使用方式对得上。
- 父子组件契约变得难以推断时，要作为问题提出。

## 多余层级

- 查是否有不必要的 wrapper、额外状态、重复转换或重复渲染分支。
- 结构冗余一般先归为建议；如果它造成理解困难、破坏项目约定或带来实际浪费，再提高严重程度。

## 测试判断

- 不要因为普通前端改动没有大范围组件测试就阻塞。
- 优先验证承载逻辑的函数和稳定的组件契约。
- 新增可复用逻辑、非平凡分支或高风险状态处理时，再提高测试要求。
