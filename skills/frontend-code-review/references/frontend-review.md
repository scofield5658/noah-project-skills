# 前端审查参考

审查 Web 界面或客户端逻辑时读取本文件。

## 重点

1. 函数和方法行为是否正确。
2. 组件用法是否符合项目习惯。
3. props 和 callback 契约是否清楚。
4. 是否引入了多余层级。

## 函数和方法行为

- 检查工具函数、事件处理、映射逻辑和派生状态，重点找会直接影响行为的问题。
- 普通 UI 改动不要上来就要求完整测试套件，先看承载行为的函数是否可靠。
- 如果新增了可复用且逻辑较重的 helper，要判断实现是否容易理解，是否值得补一个轻量测试。

## 组件用法

- 看组件是否按项目里相似组件的方式使用。
- 留意不合群的组合方式、临时 wrapper、孤立样式方案。
- 如果共享组件或 hook 已经覆盖同类行为，重复实现要指出。

## Props 和 callback 契约

- props 名称要能表达业务含义，并和项目命名习惯接近。
- 可选/必填 props 要和已有组件契约一致。
- callback 的参数、调用时机、返回值要和下游使用方式对得上。
- 父子组件契约变得难以推断时，要作为问题提出。

## 多余层级

- 查是否有不必要的 wrapper、额外状态、重复转换或重复渲染分支。
- 结构冗余一般归为建议；造成行为错误、违反明确合并要求或带来可证明的性能风险时，再按影响提高严重程度。

## 交互、状态与异步

- 沿实际交互检查加载、成功、空数据和失败状态，以及重试、取消和重复提交。检查筛选、分页或路由变化后，状态是否仍与当前操作一致。
- 涉及异步请求时，检查旧响应是否覆盖新结果，组件卸载或请求取消后是否仍更新状态；涉及 effect、订阅、定时器时，检查依赖、闭包和清理是否正确。
- 检查表单默认值、校验、禁用状态及提交结果是否一致，保留有效的 `0`、`false` 和空值语义。按调用方确认转换和展示口径。

## 渲染与使用体验

- 样式或布局变化时，按项目支持的视口检查溢出、遮挡、长内容和关键操作可见性；交互组件检查键盘操作、焦点和可访问名称。
- 涉及服务端渲染或服务端/客户端组件时，检查运行环境、序列化和首次渲染是否一致，浏览器 API 与服务端配置是否处在正确边界。
- 性能意见要对应实际热点，如重复请求、大列表渲染或无界更新；不要把所有新对象、回调或缺少 memo 都判成性能缺陷。

## 数据与安全

- 涉及 HTML、URL 或第三方内容时，检查不可信输入是否进入危险渲染或跳转路径；检查敏感信息是否进入客户端包、浏览器存储或日志。
- 权限相关改动检查展示、交互与接口返回是否一致。界面的隐藏或禁用不能作为服务端授权已生效的证据。

## 测试判断

- 不要因为普通前端改动没有大范围组件测试就阻塞。
- 优先验证承载逻辑的函数和稳定的组件契约。
- 新增可复用逻辑、非平凡分支或高风险状态处理时，再提高测试要求。
- 涉及视觉或交互行为时，优先使用已有预览、浏览器或交互测试核对；无法运行时明确标注未做视觉或运行验证，不能仅凭函数测试认定界面行为正确。
