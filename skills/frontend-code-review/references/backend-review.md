# Node.js 后端评审

审查 Node.js 服务时读取本页。沿变更涉及的入口、业务处理、依赖调用和数据副作用检查实际执行路径。先了解项目已有的 handler、middleware、service 和数据访问方式，按涉及的场景选用以下检查。

## 接口与调用契约

- 对照调用方核对输入校验、默认值、状态码、响应字段和错误结构。字段改名、类型变化或删减时检查兼容性，区分缺失值、空值和有效的 `0`、`false`。
- 页面与 BFF 联动时，检查请求、响应、错误显示和取消行为是否一致。共享类型不能替代实际运行时输入校验。

## 授权与输入安全

- 确认校验和授权位于实际执行路径，检查用户能否访问指定对象或租户的数据。认证成功不代表拥有当前操作权限。
- 输入进入查询、外部 URL、文件路径或命令时，检查对应的注入、越权或越界访问风险；只检查变更涉及的输入路径。
- 检查错误响应、日志和配置是否泄露凭据或敏感数据，复用项目已有的脱敏与错误处理机制。

## 异步、依赖与资源

- 检查 Promise 是否被正确等待或捕获，失败是否经过统一处理，是否出现提前成功、重复响应或未处理拒绝。
- 依赖调用检查超时、取消和失败返回。涉及重试时核对次数与副作用，避免失败后重复写入。
- 按负载路径检查无界并发、超大输入、同步阻塞和连接释放。流式处理关注背压和断开后的清理；任务或消息消费关注失败恢复与重复执行。

## 数据与副作用

- 数据写入检查重复请求、并发更新、部分失败和事务边界。外部调用与本地事务共同完成操作时，检查失败后的实际状态及已有恢复方式。
- 字段或 schema 变化检查旧数据、默认值、迁移与应用版本的兼容，以及回退时仍在运行的调用方；必要时结合项目的数据审查规范。
- 查询或缓存变化检查分页边界、查询次数、缓存键与失效行为，性能结论应有具体调用路径或负载依据。

## 分层与验证

- 优先复用现有校验器、服务和错误处理机制。新增封装应承担明确职责，按实际影响判断重复或分层问题。
- 沿用项目已有的测试方式，验证本次变更涉及的正常路径、无效输入、授权边界、依赖失败及数据副作用。不为未涉及的场景强行增加测试。
- 明确执行了哪些检查及结果，哪些结论来自静态阅读，哪些兼容或异常路径尚需补验。
